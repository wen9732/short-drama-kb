# 项目库｜总说明

项目库存放**用户自己要继续写下去的作品**，用来让剧情、人物、规则前后一致。它和案例库不同：

| | 案例库 `范例/` | 项目库 `项目/` |
|---|---|---|
| 收什么 | 学写法用的参考作品 | 用户正在开发、要往下写的作品 |
| 怎么用 | 只取机制，不取文本 | 事实必须继承，不能写反 |
| 谁能改 | 收录后不改正文 | 每写一集都要更新档案 |

同一部作品可以两边都有：例如《反相之地》的原稿提示词留在 `范例/短剧/反相之地/` 学写法，剧情档案放在 `项目/反相之地/` 往下写。

## 目录结构

```
项目/<作品名>/
├── 启动.md          # 项目卡：口令、必读两份档案、当前进度、默认工位（v3.0 起）
├── 项目档案.md      # 山音项目状态：世界规则、人物、时间线、道具、伏笔、版本。每写一集都更新
├── 剧情缝合与走向.md # 已知集数之间的缝合、后续走向方案。标明哪些是原稿、哪些是 AI 提议
└── 剧本/            # 定稿后的分集剧本（第09集.md……）
```

## 规矩

1. **先读项目卡再动笔。** 用户说"写《反相之地》第9集"时，先读 `项目/反相之地/启动.md`，按卡里的清单读档案，再进入编剧工位。原作提示词（案例库）默认不读。
2. **每条事实标来源**：【原稿】哪集哪条；【用户】用户明确说的；【评论】公开评论；【AI 提议】；【待核实】。AI 提议的内容，用户确认前不能当成既定事实。
3. **方向性变更先问。** 改世界规则、人物生死、主线目标之前，按 `script-shanyin` 的变更边界先交方案。
4. **写完一集就更新档案**：时间线、人物状态、道具状态、伏笔（新埋的、已回收的）。
