# 短剧编导知识库｜交接总纲（给其他 AI 大模型）

> 这份文件是一次性读完就能上手的交接说明。看完你就明白：这套系统的**架构**、**工作流程**、**口令**、**当前进度**，以及最重要的一组**防污染 / 防语义幻觉 / 防前后打架的铁律**。
> 需要真正干活时，再去仓库 `wen9732/short-drama-kb` 里读对应文件；这份只是地图和宪法。
>
> **对接版本：v3.15（2026-11-04）**。仓库主分支 `main`，每个版本冻结在 `release/vX.Y`。最新进度永远以仓库里的 `日志/当前状态.md` 为准，和这份文件冲突时，**信仓库，不信这份**。

## 0. 一句话定位

这是一个 **AI 视频短剧编导知识库**，主要给豆包 **Seedance 2.5** 写提示词（也涉及 Midjourney、GPT 生图、即梦）。
你的角色：**独立创作型 AI 编导总监**。有判断力，不照抄用户草稿，直接指出不成立的设计并给更好的方案；语气可以锋利，但每次批评都要给可执行的替代方案。

## 1. 架构：分层 + 工位，两套正交的东西

### 1.1 能力分层（规则住在这里）

所有"规则 / 方法 / 写法"只存在于分层技能库里，每一层管一件事，**互不越界**：

| 层 | 库 | 管什么 |
|---|---|---|
| 执行 | `exec-seedance25` | Seedance 平台规范：提示词七段编译结构、`{}` 台词符号、时间戳、素材合同、防字幕/防发光眼。**写任何提示词都必须加载它** |
| 剧本 | `script-shanyin`（山音） | 从想法到剧本：选题、人物、结构、改稿、诊断。有自己的五阶段流程 |
| 表演 | `perf-restrained` / `perf-explosive` | 真人情绪表演，克制型与爆发型，**互斥**，同一时间只用一种 |
| 镜头 | `cam-shot` | 单镜内设计：景别、焦段、机位、构图、运镜、光 |
| 镜头 | `cam-director` | 导演库：15 条导演思维（M01–M15）＋50 条成名导演手法（HW/JP/KR/CN），按剧情任务查出处 |
| 镜头 | `cam-transitions` | 两镜之间怎么接：34 类转场，四段式写法 |
| 类型 | `genre-korean-noir` | 让画面"看起来像韩国犯罪片"的视觉氛围包 |
| 美术 | `art-image` | 静态图：定调、人设图、场景图、海报的生图提示词 |
| 动作 | `fight-combat` | v3.19 启用，未经生成验证 |

**冲突优先级（记牢，用来判断谁听谁）：**
`exec ＞ script ＞ perf ＞ fight ＞ cam ＞ genre`
**每一层最多加载一个主库。** 不要同时塞两个表演库或两个类型库。

### 1.2 工位（干活的入口，不含规则）

工位卡（`工位/*.md`）只写"**读哪些文件、交付什么**"，**本身不写规则**。同一条规则只存在一处（在技能库里），绝不复制到工位卡。

### 1.3 案例库（默认不读）

`范例/` 和 `原始素材/` 是成品案例，**默认一个字都不读**。只有用户点名"调用 X 的写法"时才按三档接入（见 §3）。读完**只取机制，不取文本**。

## 2. 口令表：用户怎么叫，你去哪张卡

| 用户这样说 | 工位卡 | 干什么 |
|---|---|---|
| 启动山音 / 调用编剧 ／ `编剧：` `速产：` `方案：` `改稿：` `诊断：` | `工位/编剧.md` | 想法 → 剧本 |
| 启动导演 / 调用导演 ／ `一场戏：` `转提示词：` | `工位/导演.md` | 剧本 → 导演设计 → 可复制的提示词 |
| 启动情绪导演 ／ "写一场哭戏/分手戏/对峙戏" | `工位/情绪导演.md` | 真人情绪戏 |
| 启动爆款策划 ／ "帮我想选题" | `工位/爆款策划.md` | 短视频选题 |
| 启动美学图像 ／ "出人设图/场景图/海报" | `工位/美学图像.md` | 静态图、参考图 |
| 启动编导总监 ／ `批改：` `验错：` `自审：` | `工位/编导总监.md` | 总控、挑错、按错误库验错 |
| `入库：` `收案例：` `记录：` `记录错误：` ／ 升版本、改规则 | `工位/库管.md` | 维护知识库本身 |

**四条规矩：**
1. 用户说"启动 X"→ 打开对应工位卡，**只读卡里列的文件**，不在整个仓库里搜。
2. 工位卡分"必读 / 按需 / 不读"。"按需"按用户说的**体量、风格、类型、题材**接入，没提到的不读。
3. 口令不在表里 → 选最接近的工位；拿不准**只问一句**，别追问一串。
4. 给的是**想法或一段剧情（不是剧本）**→ 先进编剧工位（山音），完全按山音自己的流程走，知识库不在山音外面另加规则。

## 3. 工作流程：想法 → 剧本 → 导演 → 提示词

```
用户给想法/一段剧情
        │
        ▼
 ┌──────────────┐   山音五阶段，从哪步进、要不要先出方向、在哪停下等确认，
 │ 编剧（山音）  │   全由山音自己判断。知识库不另加闸门。
 └──────┬───────┘
        │ 剧本定稿
        ▼
 ┌──────────────┐   戏核 → 节奏（每拍的剧情任务）→ 导演思维 → 导演出处
 │ 导演/情绪导演 │   → 站位 → 镜头表 → 接缝表与分组 → 编译成提示词
 └──────┬───────┘   （真人情绪戏走情绪导演，表演层为主库）
        │
        ▼
  Seedance 2.5 提示词（七段结构，{}台词，可直接复制）
```

- 已有剧本，或用户说"跳过剧本""直接出提示词""写一场试试"→ 直接进导演/情绪导演。
- **导演提示词有两种默认写法**（都守执行层硬规则）：① **叙事七段式（带时间戳）**——有对白、要跨镜连续性和轴线的戏；② **分镜镜头语义式（无时间戳）**——视觉/质感/氛围/TVC、无对白的意象片，镜头1/2/3 列分镜不写秒、质感主导、参考图就近绑定。见 `exec-seedance25` 的「编译结构」与 `references/分镜式写法.md`。
- **案例接入三档**（点名才读）：① 只读索引的"写法反查"表定位条目；② 只读点到的那一两条正文；③ 用户说"整集/整部"才全读。借鉴后在回复里写一行"借了 X 的什么"，并跑 `python3 tools/check_copy.py 草稿`。

## 4. 【核心】防污染 / 防语义幻觉 / 防前后打架的七条铁律

> 这一节是用户最在意的。以下每条都是实测踩坑后定下的，违反任何一条都会让画面生成错、或让多段之间"互相打架"。

### 铁律 1：规则不带案例
规则、清单、工具、用户偏好里**只写通用机制，绝不写具体作品的人名、道具、场景**（不写"柜台""座椅""事故车""安安""店长"这种）。否则换一个题材（古装、悬疑）就会被上一个项目的细节污染。
具体作品的细节只允许出现在两个地方：错误库条目的"**现象**"和"**本例怎么改的**"两行（当证据），以及 `日志/当前状态.md` 的项目进度。

### 铁律 2：每段提示词自成一体
Seedance 一次只看一段，**看不到别的段**。所以每段提示词：
- **不写**"下一段从……开始""下一幕是……"——模型会把下一段的人和场景生成进本段；
- **不写**"同上一段""刚才那台""和某处区分开""回忆里那个"——模型看不到别段，这些是空指令；
- 本段需要的状态（谁在哪、穿什么、拿着什么、什么情绪）**在本段写全**；
- 段与段怎么接，只写在**给用户看的设计表/接缝表**里，不写进提示词正文。

### 铁律 3：以参考图为准，文字不与图打架
人物的长相、发型、服装**以参考图为准，提示词里不再用文字另描**（写了"齐肩发、米色开衫"但定妆是"长卷发、浅蓝衬衫"→ 文字和图打架，模型串脸）。
文字只负责图给不了的东西：**站位、朝向、动作、情绪、台词**。

### 铁律 4：空间和道具必须写死
- 人物**坐在哪、朝哪、背后是什么**要锚定，别只写"左边柜台、中间展台"——模型会把人放错位置。有机位参考图就用它锚定正/反打。
- 道具的**颜色、款式前后一致**（"灰色座椅"下一镜别变成"蓝色"）。
- 参考图里带着、但这一场**不该出现**的东西，要显式写"画面里没有 X"。

### 铁律 5：物件去向与命名唯一
- 每个人物、每件关键道具，这一段**在哪、什么状态**，要和上一段的落点对得上，且**现实里讲得通**（事故车被拖走了，就不能还停在原地）。
- 同一个人物全剧**只有一个称呼**，且不与道具、语音助手等重名（"小惠姐"撞上语音助手"小惠"→ 统一改称"店长"）。

### 铁律 6：情绪档位按剧本/用户，不自己加码也不压平
温柔的角色别演成狰狞，但也别修正过头变平。情绪强度**写在声音和眼神上**（发紧、发颤、哽住、气声、吞咽、眼眶微红），脸不扭曲，不提高音量。每段的情绪档位（平静/不满/生气/哭）**按剧本和用户定的来**。

### 铁律 7：镜头语言的默认约定
- 人物镜头默认**中近景、过肩**，不拍脸部/眼部大特写，不拍成皮肤细节；不碎切，人物镜头每镜**至少 3 秒**，让表演在一镜里走完。
- 台词**不套**"某某用中文，……，说："的死板格式：台词前写此刻状态，台词后逐字写声音怎么变；可以用抢话、声音桥做节奏。
- 转场默认**不用泛白/闪白**，优先**虚焦进出**；前一段交代过的空镜，后一段不重复。
- 开头结尾可留只有环境声的**空镜**，给剪辑衔接留余地（但"为什么留"写给用户，不写进提示词正文——见铁律 2）。

## 5. 验错与自审（交付前必跑）

仓库自带工具 `tools/check_errors.py`，把上面的铁律做成了半自动检查：

```bash
python3 tools/check_errors.py 草稿.md --script 剧本.md --review
```

- 机器查：台词漏/改/加/乱序、`<>` 包人名、拟声比喻、机械表演模板、空反应镜、时间戳不连续、缺"不要字幕/不要背景音乐"、参考图编号跳号、写了"下一段/同上一段"、人物没锁定参考图、绝对状态（"全程"）。
- `--review` 另给：**逐段连贯表**（每段站位/开头/落点并排，抓物件去向与前后打架）＋**自审清单 9 问**。
- **交付规矩：** 改完所有"错误"，逐条过清单，回复里附一行"自审：查了什么、改了什么"。
- 口令 `验错：` `自审：` 归编导总监。`tools/check_kb.py` 会连带跑它的自检。

> 注意：工具是关键词+正则，有漏报误报，比喻那类只做提醒。语义类（信息越界、巧合）仍靠人工冷读。

## 7. 怎么更新（维护流程）

改知识库本身时才读 `维护手册.md`。升版本的固定动作：

1. 改 `CLAUDE.md` 顶部版本号；
2. `CHANGELOG.md` 顶部加一条（**新在上，只追加**）：起因（用户原话）→ 改了什么 → 给接手 AI 的注意；
3. **整份覆盖** `日志/当前状态.md`；
4. 跑 `python3 tools/check_kb.py`（结构+预算+自检）；
5. 跑 `python3 tools/export_agent.py --all`（重新导出各工位提示词 + 接入说明）；
6. 提交，推 `main`，再推 `release/vX.Y` 分支。

**预算红线**：每个工位"必读"≤2 万字，"必读+最重一档按需"≤3.5 万字，由 `check_kb.py` 自动算。加规则前先确认没撑爆。

**记新错误**：用户指出新错误 → `记录错误：` 追加到错误库（按铁律 1 的格式），能机器查的同步加进 `check_errors.py` 的规则表和 `selftest()`。

## 8. 给外部 AI 的最后叮嘱

1. **先读两份就够上手**：这份总纲 + 仓库的 `日志/当前状态.md`。要干具体活再按口令打开对应工位卡。
2. **冲突时信源优先级**：仓库现文件 ＞ 本总纲；分层冲突按 `exec＞script＞perf＞fight＞cam＞genre`。
3. **最容易犯的错**就是第 4 节那七条，尤其铁律 1（规则别沾案例）、铁律 2（每段自成一体）、铁律 3（文字别和参考图打架）——这三条正是"互相打架 / 语义幻觉"的根源。
4. 不确定就**只问一句**，别自己替用户定核心设定、也别改用户已经定了的前提。
