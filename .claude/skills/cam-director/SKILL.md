# 镜头层·导演库

## 边界
- **负责：** 导演层面的思维（怎么想一场戏）和手法（成名导演在具体电影里解决具体问题的机制），以及它们的出处、适用与禁用场合。
- **不负责：**
  - 镜内景别、焦段、运镜的通用写法 → `cam-shot`；
  - 转场类型、切点、剂量 → `cam-transitions`；
  - 演员怎么演 → `perf-`；
  - 色调与类型氛围 → `genre-`；
  - 打斗设计 → `fight-`（未建）；
  - 设计流程和编译格式 → `exec-seedance25` 的导演语法。
- **互斥：** 无。镜头层按子域分库，可与 `cam-shot`、`cam-transitions` 叠加。
- **常搭配：** `exec-seedance25`（导演语法）＋ `cam-transitions`。

## 一句话原则
导演名是出处，机制是内容：先按剧情任务找到验证过的方案，再拆成机制写进自己的戏。

## 文件
- `references/导演库总表.md`：15 条思维的一行版、按剧情任务选手法的表、编号与文件对照、用法纪律。**导演工位必读。**
- `references/导演思维.md`：M01–M15 细目，每条写问题、做法、出处、落到设计、反例。
- `references/导演手法/`：
  - 好莱坞：`好莱坞-1.md`（HW01–HW10）、`好莱坞-2.md`（HW11–HW17）、`好莱坞-3.md`（HW18–HW23）；
  - 日本：`日本.md`（JP01–JP10）；
  - 韩国：`韩国.md`（KR01–KR10）；
  - 华语：`华语.md`（CN01–CN07）。

  每条写出处、机制、用在、Seedance 写法、常配接缝、别用在。

## 新导演入库（口令：`入库：导演 <名字>`）
1. **先查重：** 名录里已有这位导演，就在他的编号后面续号；已有同一机制的条目，就补出处，不新开一条。
2. **找出处：** 联网找访谈、摄影师手记、权威影评（American Cinematographer、BFI、Film Comment、Bordwell 等）。找到就标【已核】并写明来源名，找不到就标【公认】。不编造场景细节。
3. **编号：**
   - 手法用两个字母的地区码接两位数字，接着本地区最后一个号往下排。两个字母是为了不和案例编号（K、B、C、D、G、S、A、T-）、转场类型（T01–T34）撞车。
   - 新地区加一个新地区码，比如 EU＝欧洲，并在总表第三节和 `范例/README.md` 的占用前缀里写上。
   - 思维条目用 M 加两位数字。
4. **写进文件：**
   - 写进本地区最后一份文件；那份文件超过约 6000 字，就新开 `-N.md`，并在总表第三节和本页"文件"段写上编号范围。
   - 手法条目格式固定，六项缺一不可，检查脚本会校验：
     ```
     ### HW24 导演名｜一句话标题
     - **出处：** 片名与场景。【已核】来源名 ／ 【公认】
     - **机制：**
     - **用在：**
     - **Seedance 写法：**
     - **常配接缝：** T 编号
     - **别用在：**
     ```
   - 思维条目的五项是：问题、做法、出处、落到设计、反例。
5. **挂上索引：**
   - 在本页名录里加一行；
   - 在总表第二节，把新条目编号补到对应剧情任务那一行，没有合适的任务就加一行；
   - 新的思维要补进总表第一节。
6. **校验与记录：** 运行 `python3 tools/check_kb.py`，它会检查编号唯一、六项齐全、出处分级、引用的手法、思维、转场编号都存在、名录完整。通过后在 `CHANGELOG.md` 记一条。
