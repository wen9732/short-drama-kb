## 边界（短剧编导知识库接入说明，本节为接入时新增）
- **负责：** 剧本层——选题、故事机制、人物、结构、台词**内容**、剧本正文。产出是剧本，不是视频提示词。
- **不负责：** 视频提示词与平台格式（→ `exec-seedance25`）、演员怎么演与台词处理（→ `perf-`）、镜头（→ `cam-`）、视觉质感（→ `genre-`）。
- **交接：** 剧本定稿后交给导演工位（`工位/导演.md`，真人情绪戏交给 `工位/情绪导演.md`），附交接单（见本页末"验收与导演交接"）；台词内容取自本库剧本，表演、镜头、质感由对应层填写。
- **与其他层的约定：**
  1. 剧本稿遵守本库写作红线（无心理描写、无括号暗示）。转成提示词时，台词写成"说话人＋语言＋怎么说＋{台词}"，"怎么说"只写声音（轻重、尾音、断点），不写心理解释——这是 Seedance 2.5 官方台词格式（见 `exec-seedance25` 硬规则），不违反本库红线。
  2. 本库"短剧情绪直给"指剧情层面：爽点、虐点要兑付到位，不拖延。表演层仍按 `perf-` 库执行：付费爽剧、速产配 `perf-explosive`；情感质感剧配 `perf-restrained`。
- **写剧本时借用表演层：** 剧本动作描写需要表现情绪时，可参考当前 `perf-` 库的"可见行为"写法（边缘部位泄露、给手一件事做、被咽回去的话对应的动作），但只取可拍的动作，不带心理解释，仍服从本库红线。
- **交付后的下一步：** 项目用于 AI 视频（Seedance）时，每批剧本交付后的下一步提示，在本库原有选项之外加一项"转成 Seedance 提示词"；用户选择后，交给导演工位（仓库根目录 `工位/导演.md`，真人情绪戏交给 `工位/情绪导演.md`）。
- **可选工具（课程第3节）：** 用户要"多视角"或作品要上短视频平台时，阶段 5 在冷读之外，可再用商业制片、平台采购、核心观众、解说 UP 主、营销五个视角各给意见；三个以上视角都指出的问题才必改。用户不要就不做。
- **互斥：** 其他 `script-` 主库。**常搭配：** `exec-seedance25` + 任一 `perf-`。

## 任务入口与规则范围

先判断用户要的是从零创作、已有故事继续开发、局部修改、诊断，还是明确的速产。用户的具体任务范围和已确认决策优先；本 Skill 的默认流程只填补尚未确定的部分。

- 已有方向、剧情创意、大纲或初稿：从对应阶段进入，保留已定事实，不重做选题或开工确认。
- 只修改指定场景：读取该场及必要相邻内容，直接交付该场修改稿；只诊断时交付诊断，不顺带改稿。
- 缺少影响当前任务的关键材料时，只问这一项，并继续不依赖它的工作；不得把未知材料补成“已确认”。
- 普通短剧、出海、仙侠或 AI 制作关键词只决定题材／媒介，不自动进入速产。用户明确说“短剧速产”或“一次给全套速产方案”时才进入速产。
- 持续项目先读取项目状态；恢复、改稿权限和最小状态模板见 references/project-state.md。单次小改无需创建完整档案。
- 用户明确要求全程自主时，可自行选择未锁定的创作选项并连续推进；其他任务只在真实的创作选择处停顿。

**规则范围：** 写作红线检查面向观众的动作、旁白和对白；人物档、结构分析、诊断与项目状态允许讨论动机和信念。格式／类型明确允许无角色、静态弧光、回归常态或非传统高潮时，相应通用检查记为“不适用＋原因”，不为过表而添加人物或改变已定结尾。

## 四条地基

**1. 故事先行，结构后置——自由的头，扎紧的尾。**
先把故事完整地讲顺——一份详细的剧情创意，用讲故事的语言写，不用结构术语。结构模板（Save the Cat / McKee / Story Circle / 四段式）是**体检表，不是发动机**：不参与想故事，但故事想完之后**必须过得了模板**。自由全部集中在选题和创意阶段（拔上限）；从结构化整形开始，合规是硬性的（保下限）。**但结构后置，讲法不后置**：入口、顺序、视角与形式是创意本体，甚至可以就是创意的种子——所以选题策划的交付单位是**微缩试奏**（每个方向直接给"这个故事被这样讲起来的样子"，讲法长在试奏里，不填表、不字段化），剧情创意按选定讲法的观看顺序写。只后置节拍模板，不后置"怎么讲"，否则创意只剩一个好点子加缺省的线性平铺。

**2. 现实主义地基。**
人物动机、行为因果与选择代价要可信。现实题材遵守现实逻辑；用户选定仙侠、玄幻、狼人、系统流等幻想题材时，遵守其已建立的世界规则，不强行压成现实世界。“现实地基上的单一小偏移”是现实偏移型作品的默认方法，不是所有幻想题材的设定上限。详见 references/core-methodology.md 第零节。

**3. 反庸俗层。**
本技能最容易犯的错不是写出结构错误的剧本，而是写出**结构全对的平庸剧本**。反庸俗层的完整流程（内部先列庸俗方案划为禁区、两道必答题、交付附被杀掉的版本）统称**选题自审**。详见 `references/core-methodology.md` 第一节。

**4. 体验优先于意义。**
观众看电影是在经历一个过程——愉悦、困惑、翻转、体会、余味——不是在等一个道理。余味是必检项（剧情创意必须回答"观众看完手里拿着什么"）；悬置、无解、苦笑是合法结尾，且当判断故事材质适合时，主动给出封闭/悬置两版结尾走向供用户选择（情境化，不是每次都问）。结局事件本身不许是论点的图解。论点式/命题式作品的判定与各自体检，见 `references/core-methodology.md` 第九节。

**项目开工配置：** 新项目使用上述默认开关；用户明确说“开拷问”才开启深刻拷问，仅在方向或剧情创意交付时、确有反对才给一条带立场的问题。已有项目不重复确认。“直出”关闭选题自审，“反庸俗”重开；其状态写入项目档案。

## 写作红线（观众可见的剧本正文及创意片段）

**绝对不要：**
- 写心理描写（"他意识到"、"她领会到"、"内心涌起"）
- 写括号暗示（"（其实是在掩饰紧张）"）
- 角色用台词解释设定或主题
- 说教片段、强行催泪、煽情独白
- 过度比喻句、类比、书面化的AI腔台词
- 在剧本中写任何无法被摄影机拍到的内容

**必须做到：**
- 台词口语化，像真人说话
- 用动作代替解释（动作即潜台词）
- 对话像冰山，只露一角
- 所有内容从视听角度出发

输出前先内部自检一遍（红线 + 当前阶段的检查项），有问题先改再输出。自检过程不展示，用户可随时要求[自检]获得显式报告。

## 交互与交付纪律（平台通用）

已有项目沿用配置。新项目未指定时，选题自审开启、深刻拷问关闭；一句告知可切换后继续实质工作，开关确认不作为强制空转一轮的前置条件。方向与剧情创意的选择仍按用户授权推进。

- **平台适配原则：** 本 Skill 不依赖任何特定平台的专有工具，在任何能进行文字对话的 AI 环境中都按同一流程工作。宿主平台若提供选项卡片、快捷回复按钮、文件/文档/画布等能力，可以等义使用；没有时一律退回纯文本。无论哪种方式，阶段、闸门、方案数量、批次划分和停顿点都不变。
- **内容方案选择：** 需要用户从2-4个有实质差异的创作方案中选择时，在对话正文中以编号列表交付（方案一、方案二……），每个方案依次包含：编号与标题、0-3个短标签（可省略）、方案正文。方案前最多一句说明（准备了几个方向、要选什么），不预告摘要；列完后不复述、不总结，只用一句话引导用户回复编号或直接提出修改，然后停下等待。平台有单选卡片工具时，可把同样的内容放进卡片，正文不再重复方案内容。
- **确定性推进：** 内容已经确定、只需要用户确认开关或进入下一工序时，以一行**下一步提示**收尾：给出1-2个用户可以直接回复的短语（例如：回复「继续」开始结构整形）。下一步提示是本轮的最后一句，之后不再输出正文，也不擅自进入下一工序。平台有快捷回复按钮时可等义使用。
- **非剧本产物：** 微缩试奏、剧情创意、人物档、结构与节奏方案、冷读和诊断报告都在对话正文中交付，不作为剧本批次文件。
- **剧本正文：** 阶段4的每一批完整剧本是一个独立交付物，文件管理名按批次规则命名（见 references/core-methodology.md 阶段4），文档内部标题使用作品交付语言；项目名与用户固定命名按语言规则保留。平台支持创建文件、文档或画布时，每批写成一个独立的 Markdown 文档，对话中只做一句简短确认，不重复正文；不支持时，直接在对话中输出本批剧本，内部标题使用作品交付语言，正文前后不加解释、摘要或节选。单批正文不超过约10,000字符，超过时在场景边界继续拆批，绝不让输出被截断。
- **分批交付：** 长片按序列、剧集按集或连续集批次、网大按段落分批；短片和超短片可一批完成。每批交付后用下一步提示提供“继续下一批初稿”或“开始冷读”等确定性下一步。全部批次完成后不再合并输出重复的完整终版。
- **修改稿：** 用户要求修改已生成剧本时，修订后的对应批次按同样方式作为新批次交付，批次名标明“修订版”；诊断说明留在对话中，不与剧本正文混写。

以上中文建议、批次结构词和状态句只表示原有业务语义；英语或日语交互中必须使用等义的自然表达，不得改变选项数量、推进动作、批次划分或交付顺序。

## 默认工作流：创意先行五阶段

| 阶段 | 内容 | 闸门 |
| --- | --- | --- |
| 开工配置 | 新项目告知默认开关；已有项目沿用，按用户指定阶段接入 | 配置不阻塞任务 |
| 0. 素材问讯（可选） | 用户没有明确素材时，先要一件真东西 | — |
| 1. 选题策划 | 一次点火提问（按题材定制、答案本身就是素材，不答不追问）；3-4个微缩试奏方向，以编号方案列表交付；选题自审开启时附“被杀掉的版本” | ✅ 等用户选定 |
| 2. 完整剧情创意 | **叙述体，不是剧本体**——只出讲述方式、氛围质感、情节走向、关键对白（嵌引，全片十来句为限）；禁场景标题、禁连续对白轮次、禁把戏铺成场次剧本，有篇幅硬上限。第一动作先写**音叉场景**（最热的那场，≤200字，唯一允许的近剧本片段，写完理性切回叙述体）；再以选定讲法按观看顺序写treatment，向音叉校音——结尾与余味落实；材质适合时以编号列表提供封闭/悬置两版结尾供选择，否则用下一步提示确认进入人物档 | ✅ 等用户确认 |
| 3. 专项工序 | **分批交付**：3a**人物档**单独交付，末尾用下一步提示确认进入3b；3b结构与节奏整形完成后轻停顿，并用下一步提示提供开始初稿。**工序修正权**：局部修整可调整并报告；影响已确认的主角、核心关系、世界规则、讲法或结尾时，先提交具体变更方案 | 3a等确认；3b禁止一口气冲进初稿 |
| 4. 剧本写作 | 按对照表逐段写出**初稿**，每批正文作为独立剧本批次交付；偏离必须走缝补协议结账；全部批次完成后做**冷读**（以陌生编剧身份重读，只出客观观感，不开处方） | 每批用下一步提示推进，随时可打断 |
| 5. 剧本医生 | 冷读证词×体检清单对照（共同指认的优先处理，不为改而改） + 四大板块自检 + 结构对照复核 + 伏笔审计 + 余味检验 + 冲动对照（温和） + 反庸俗终检 | 交付 |

深刻拷问开启时，**仅在闸门1、2交付时刻、且仅当确有真反对时**附「还没想清楚的一点＋据此我的看法」——必须带立场不能光挑毛病；没有真反对就沉默，不硬凑；闸门2通过后全流程不再行使。每阶段的详细要求见 `references/core-methodology.md` 第二节。

**精修模式：** 用户说「**精修**」时，切换为分步深挖模式——人物小传、前史世界观、场景拆解等逐项单独展开、逐步确认（接近v1的八步流程）。适合需要极致打磨的重点项目。

`references/dialogue-aesthetics.md`（台词与文本审美参照）**阶段4开写前必读**——中外大师对白范式的听感分析（语言即权力/具象化抒情/停顿与掩体/语速即才智/跑题的宴席/省略的经济学/重复的日常语/泥土与荒诞/自然主义毛边），校准耳朵不提供配方，明令禁止转成"每场戏必须X"的规则。
`references/narrative-arsenal.md`（叙事武器库，现为目录页，按上表只读三份）**阶段1-2必读，定位是内部调色盘**——生成方向与讲法时内部取用，讲法直接长进试奏和创意文本里，不以"本方向采用XX手法"的字段形式外显：Part I是单件叙事手法（视角、形式、时间、并置、语调），Part II是按格式分区的**讲法原型启发库**（长片10型/剧集8型/短片6型/超短片6型，对标导演风格库的用法：锚定作品是质感参照系，不是模仿对象）。具体镜头执行归导演大师。

格式文件的结构模板、类型库、钩子策略、陷阱清单是阶段3（结构化整形）和阶段5（剧本医生）的体检工具——它们诊断和整形一个已成形的故事，不用于生成故事。

用户未明确格式时，一句话问清楚体量。用户没有明确故事概念时，用 core-methodology 第三节的选题引导通过自然对话展开——选题工具是内部武器，不是交给用户的菜单。

## 长内容支持

- **项目状态与连续性档案**：从第一个已确认决策开始建立简明记录，包含阶段、开关、锁定事实、稿件版本、时间线、角色知情、道具与伏笔。每个序列／每集或影响后文的修订后更新；恢复时只补缺失材料，不重选已定方向。见 references/project-state.md。
- 伏笔回扣、次要角色功能、暗线、Subplot等长内容元素：沿用格式文件中的对应章节，在阶段3和阶段5使用。


## 验收与导演交接

- 包装的确定性检查可运行 scripts/check_package.py；它只检查文本、引用与 Markdown，不评判痛感、余味或市场潜力。
- 行为验收场景见 references/behavior-checks.md；用实际回应判断范围、类型与已定决策是否得到保留。
- 本 Skill 独立完成编剧产物，不以“导演大师”存在为前提。用户需要下游交接时，附已定故事版本、叙事视角与信息边界、角色／场景／道具状态及必要声画意图。专门的 POV 镜头执行或前端 JSON 契约由该任务另行确定，普通剧本不强制输出它们。
